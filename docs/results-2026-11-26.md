# Measured results — dual-head BEVFusion vs the new 2D pipeline

All figures are `iou@max` unless stated, on lanelet2 or municipality-derived GT.
Every number here comes from a log that still exists on csc3 under
`~/wato/ablate*.json` / `~/wato/agent/logs/`.

## 1. The fused map head is worse than the camera branch alone

`epoch_22` (A5, not fine-tuned), same frames, same masks, only the input changed:

| input | old lidar (233 fr) | new VLS-128 (105 fr) |
|---|---|---|
| base (camera + lidar) | 0.1063 | 0.1309 |
| **no lidar** | **0.1101** | **0.1429** |
| lidar clipped to 10 m | 0.1104 | 0.1418 |
| lidar clipped to 30 m | 0.1051 | 0.1381 |
| lidar xyz shuffled | — | 0.0942 |
| lidar clipped to 40 m | — | 0.1361 |

Monotonic: the less LiDAR the better, and shuffling xyz collapses the score, so
the fuser is consuming the cloud — just unhelpfully.

## 2. No calibration parameter explains it

Flat within ±0.002 on 105 frames: yaw ±1/2/5/10/20/30/45/50/180°, pitch ±1/3°,
z ±0.2/0.5 m, x/y ±0.5/1.0 m, scale ±2%, intensity zeroed, density 50%.
A 50° extrinsic error would have jumped at yaw±50. It does not.

## 3. Class parity (the honest number)

Same classes as nuScenes, `stop_line` excluded because our lanelet maps give
zero stop-line frames in this sample:

| class | nuScenes val | EVE (camera-only, 105 fr) |
|---|---|---|
| drivable_area | 0.7348 | 0.387 |
| ped_crossing | 0.3498 | 0.000 |
| walkway | 0.4537 | 0.070 |
| divider | 0.3190 | 0.042 |
| carpark_area | 0.3419 | 0.007 |
| **5-class mean** | **0.4398** | **0.1012** |

The big-area class transfers at ~53% of in-domain quality; every structured
class collapses. Caveat: our walkway/carpark GT is OSM footpaths and parking
polygons, a different ontology from nuScenes, so those two rows overstate the
failure. drivable and divider are the fair comparisons.

## 5. Why LiDAR paint extraction is closed

Full-bag scan of 8 bags (1,687 frames) plus a 10-sweep accumulation test:
density 18 → 175 points/m², paint AUC 0.561 → 0.557, and intensity **on a
visible white lane line is 25.0 vs 25.0/24.0 on the asphalt either side**.

So the "lane lines" visible in a BEV of this sensor are the beam-ring footprint
(concentric, ~1.4 m spacing, present on grass and car parks), not paint, and
under-sampling is not the cause. Details and images:
`docs/vls128-2026-11-24.md`.

## 6. Data sources evaluated

| source | usable for | licence |
|---|---|---|
| City of Waterloo Sidewalks (17,111 centrelines) | walkway | open, NAD83 UTM17N |
| Region of Waterloo open data (single-line street network, trails, parking) | drivable/walkway/carpark | OGL-style |
| OSM footways/paths/parking | walkway, carpark | ODbL |
| Kitchener/Waterloo 12 cm orthophoto | paving polygons | open |
| **ACDC** (2,006 labelled adverse frames) | **night/fog/rain/snow segmentation** | research only |
| **CADC** (Waterloo, snow) | domain validation, lidar self-supervision | CC BY-NC 4.0 |

ACDC ships Cityscapes **labelIds** (road=7, sidewalk=8) and an invalid mask
`_gt_invIds.png` inside `gt_trainval.zip` — there is no separate masks download.
Night has 33% invalid and 26% drivable pixels, so effective supervision per
night image is about a third of a fog image.
